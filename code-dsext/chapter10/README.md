# 第十章：工业数据协议协作中枢

本示例对应
[`Chapter10-DSExt-IndustrialDataProtocolHub.md`](../../docs/chapter10/Chapter10-DSExt-IndustrialDataProtocolHub.md)，
实现一个离线、只读、可审计的工业数据协议协作中枢。系统使用 MCP 风格工具契约暴露
脱敏数据能力，用 A2A 结构化消息串联四类专业智能体，再由 ANP 注册表按数据域、权限、
算法版本、健康和负载选择分析服务。

代码只使用 Python 标准库，不启动网络端口，不调用 LLM 或外部 API，也不连接真实
时序库、MES、QMS、PLC、DCS。它演示协议职责和治理边界，不是生产协议栈或控制系统。

## 协议职责

| 协议 | 本示例职责 | 不承担的职责 |
| --- | --- | --- |
| MCP | 发现并调用五个标准化只读数据工具；声明输入、单位、范围、行数和错误 | 不进行服务调度，不控制设备 |
| A2A | 在数据质量、时序分析、设备诊断和报告智能体之间传递结构化任务与证据 | 不只传自然语言摘要，不替代人工根因确认 |
| ANP | 发现同能力服务，并按数据域、租户、版本、负载、超时、健康和追溯能力选取 | 不自动降权、跨租户或绕过权限兜底 |

同一个 `request_id` 贯穿三层协议，便于把服务选择、工具调用、智能体消息和最终报告
串成一条审计链。

协议中枢会先校验访问令牌，并要求令牌租户与任务租户完全一致；认证或租户绑定失败时
不会进入 ANP 服务发现，因此不能借伪造任务范围探测其他租户的服务元数据。

## 快速运行 🚀

在仓库根目录运行默认振动异常场景：

```bash
python -X utf8 code-dsext/chapter10/examples/run_protocol_hub_demo.py
```

查看完整的跨协议 JSON 消息、证据和审计：

```bash
python -X utf8 code-dsext/chapter10/examples/run_protocol_hub_demo.py \
  --request-id REQ-CH10-DEMO-002 \
  --format json
```

完成分析返回退出码 `0`；服务无匹配、认证失败或上游不可用而降级时返回 `2`；输入或
配置错误返回 `1`。默认访问令牌是固定的本地教学标识，只映射到 `tenant-a` 的读取
权限，不是生产密钥，且不会进入输出或审计。

## MCP 工具契约

| 工具 | 权限 | 主要边界 | 确定性输出 |
| --- | --- | --- | --- |
| `list_equipment` | `equipment:read` | 只返回当前租户设备 | 设备、产线、测点、单位、采样频率 |
| `query_timeseries` | `timeseries:read` | 带时区时间窗不超过 24 小时；最多 50 行 | 原始点、单位、最小/最大/平均值与截断状态 |
| `get_batch_quality` | `quality:read` | 批次必须属于当前租户 | 产量、合格量和确定性一次合格率 |
| `lookup_alarm_event` | `alarm:read` | 带时区时间窗不超过 24 小时；最多 50 行 | 告警事件、总命中数与截断状态 |
| `get_data_dictionary` | `dictionary:read` | 只能读取固定本地字典 | 字段类型、单位、采样频率和说明 |

`list_tools()` 返回包含 `inputSchema`、`outputSchema`、只读注解和错误码的能力描述。
输入使用白名单字段校验；未知参数、超窗、超行数、无权限、跨租户和限流都会返回
结构化错误。系统不注册 `set_parameter`、`start_machine` 等控制工具，调用它们只会
得到 `TOOL_NOT_FOUND`。

协议边界会遮盖 `inspector_name`、`acknowledged_by`、令牌、密码、电话和邮箱等敏感
字段。限流按“操作者 + 工具”计算，默认每分钟 60 次。

## A2A 消息与报告

每条 `A2AMessage` 都必须携带：

- `request_id`、`task_id`、发送者、接收者和能力声明；
- 设备、测点、开始时间和结束时间组成的 `input_data_range`；
- 可定位到源文件、数据范围和 SHA-256 摘要的 `evidence_refs`；
- `succeeded`、`degraded` 或 `failed` 状态，以及失败时的结构化错误；
- 结构化事实、假设和未知项，而不是不可验证的自然语言转述。

协作顺序为：

1. `data_quality_agent` 检查缺失、时间对齐、单位和采样频率；
2. `timeseries_agent` 计算首末变化、最大相邻突变和周期相关候选；样本不足时明确未知；
3. `equipment_diagnosis_agent` 查询告警并形成带“可能、相关、不能确认根因”的假设；
4. `report_agent` 合并事实、假设、未知项、证据和人工复核下一步。

所有数值都来自确定性代码和固定样例；报告不会把时间共现写成因果结论。

## ANP 服务选择

`services.json` 包含同能力但数据域、租户、算法版本、负载和健康状态不同的教学服务。
注册表先过滤以下硬约束：

1. 能力、产线、时间范围和租户权限；
2. 算法名称及最低版本；
3. 最大负载、最大预计超时和健康状态；
4. 是否支持结果追溯。

通过过滤的候选按“负载、超时、服务 ID”确定性排序。没有候选时流程停止在 ANP 层，
不会跨租户、降低算法版本或跳过追溯要求自动兜底。

选定服务后，注册表继续生成可审计的 `dispatch_task` 记录。时序智能体从这份分派中
取得服务 ID、算法及版本，并把实际执行信息写回 A2A 消息，避免“只选择、不分派”。

## 超时、重试与降级

`IndustrialMCPClient` 把 `timeout_seconds` 传给传输层，默认最多重试 1 次。本地
`InProcessTransport` 使用守护线程执行只读调用，并按墙钟时间立即返回超时；Python
无法强制终止已经启动的线程，因此超时后的本地只读处理可能在后台完成，但其结果不会
进入当前分析。生产网络传输仍应使用可取消的连接和请求级超时。重试预算耗尽后返回
`degraded`，记录尝试次数、错误码和降级说明，不伪造分析结果。ANP 无匹配时不启动
A2A；认证、读取失败或有效时序样本不足时，下游报告明确标记“未生成分析结论”。

## 数据、证据与审计

- `equipment.json`：三个脱敏教学设备及其租户、产线、测点和单位；
- `timeseries.csv`：两租户的固定泵组教学时序；
- `batch_quality.csv`：固定批次质量摘要，人员字段在协议边界遮盖；
- `alarms.csv`：固定教学告警，确认人字段在协议边界遮盖；
- `data_dictionary.json`：测点类型、单位和采样频率；
- `services.json`：ANP 服务发现与选择样例。

证据 ID 由操作、源文件摘要和确定性结果生成；相同输入与源数据得到相同证据 ID。
审计 ID 与 UTC 时间每次调用独立生成。每条审计记录保存协议、服务、操作、参数摘要、
响应字节数、状态、错误码和证据 ID，但不保存访问令牌或未遮盖人员字段。

全部数据均为 2026-07-29 人工构造的脱敏教学标识，不来自真实企业，不能用于工艺
放行、设备控制或现场处置。

## 最小假设

- 时间采用带时区的 ISO 8601；查询端点均包含开始和结束时刻；
- 单位和采样频率以 `data_dictionary.json` 为准，不在模型中推断；
- 算法版本使用仅含数字的 `major.minor.patch` 比较；
- 本章实现协议语义与治理契约，不实现 FastMCP/A2A/ANP 的网络线缆传输；
- 若未来增加真实控制能力，必须放入独立安全域，引入不可绕过的人工审批、双人复核、
  独立审计和现场安全评估；本教学中枢不会自动开放这类能力。

## 安全边界 🔒

- 模型或智能体不能拼接任意 SQL、Python 或 Shell；只能调用已注册的只读工具；
- 访问令牌映射租户和工具权限，源数据查询始终再次按租户过滤；
- 敏感字段在 MCP 响应和审计写入前遮盖；
- 异常、趋势和告警共现只形成假设，不等于根因；
- 跨域取数、生产试验、工艺变更、最终根因和任何控制动作必须由相应负责人审批。
